# Powermon - collector for power consumption monitoring
## Goal
This monitor is used to read [prometheus-style text](https://prometheus.io/docs/instrumenting/exposition_formats/#prometheus-text-format) to retrieve power consumption information.
## Power consumption metrics
Several power consumption metrics are available in current machines.
- [HWMon](https://docs.kernel.org/hwmon/hwmon-kernel-api.html) (HardWare Monitoring) provides access to several sensors in the machine. From these, some show power consumption in watts. However, these quantities may monitor different subsets of the machine.
- [IPMI](https://www.intel.la/content/dam/www/public/us/en/documents/specification-updates/ipmi-intelligent-platform-mgt-interface-spec-2nd-gen-v2-0-spec-update.pdf) (Intelligent Platform Management Interface): several IPMI_power_watts metrics are available on the same machine and each manufacturer adds a different tag to each monitor. 
- [RAPL](https://hubblo-org.github.io/scaphandre-documentation/explanations/rapl-domains.html#explanation-on-rapl--running-average-power-limit-domains-what-we-think-we-know-so-far)  (Running Average Power Limit) is a technology implemented by Intel in 2012 (starting from the Sandy Bridge architecture) and later implemented by AMD as well. RAPL uses sensors inside CPUs to monitor the energy consumption and store it in a counter. This sensors are available regardless of provider (Dell, SuperMicro...) and are very reliable. However, they only monitor a subset of the machine.
    - RAPL provides three different metrics: core (consumption of the cpu cores), dram (the attached RAM) and package (whole CPU die). Hence, this metric does not account for the consumption of other parts of the machine such as disks or fans.
    - This technology is implemented differently in Intel and AMD. Intel CPUs report consumption for all cores in the core metric (`rapl_core_joules_total`). However, AMD provides this metric per core and the linux kernel only reads the first value of the register so only the power consumption of the first core is stored.
- [DCMI](https://www.intel.com/content/dam/www/public/us/en/documents/technical-specifications/dcmi-v1-5-rev-spec.pdf) (Data Center Manageability Interface) is a subsystem of IPMI that focuses only on server power management. The standard states that it must monitor the consumption of the whole machine.
## Access to metrics - Prometheus and others
Several ways to monitor power consumption are available at sites. A simple way to provide access to these metrics is through a prometheus exporter (e.g. [IPMI exporter](https://github.com/prometheus-community/ipmi_exporter) for IPMI and DCMI metrics or the generic [node exporter](https://github.com/prometheus/node_exporter) for HWMon and RAPL, among many other metrics). Alternative possibilities are also being explored and tested by HEPiX, see [here](https://gitlab.cern.ch/hep-benchmarks/hep-power-collector/-/tree/master?ref_type=heads). 

The `powermon` collector is able to read either from a URL via cURL or a given file as long as it the text uses [prometheus-style format](https://prometheus.io/docs/instrumenting/exposition_formats/#prometheus-text-format). Location of files or internal URL can be configured via the environment variable `PROMETHEUS_LOCAL_URL`. The contents of the file/url are then parsed to extract the available metrics' values.
